# 博客写作规范

这份规范用于后续撰写和维护博客文章。它不是强制模板，优先保证内容清楚、阅读舒服、后续容易维护；如果写作过程中形成了更好的做法，可以继续补充到这里。

## 基本原则

- 文章优先服务读者理解，不为了形式牺牲信息密度。
- 标题、目录、图片、代码块都应帮助读者快速定位关键信息。
- 技术记录可以保留过程和排错细节，但要尽量说明背景、步骤、结果和注意事项。
- 涉及账号、支付、密钥、内网地址等内容时，发布前必须检查是否包含敏感信息。

## 推荐结构

常规技术文章可以参考下面结构，但不必每篇都完全一致：

```markdown
---
title: 文章标题
date: YYYY-MM-DD HH:mm:ss
categories:
  - 分类
tags:
  - 标签
---

开头说明本文解决什么问题、适合谁读、最终结论是什么。

## 背景

## 环境

## 操作步骤 / 实现过程

## 问题与排查

## 总结
```

## 图片规范

图片目前统一放在 `source/images/` 下，文章中使用站点根路径引用：

```html
<img src="/technological_blog/images/example.png" alt="图片说明" style="max-width:300px;width:100%;height:auto;display:block;margin:18px auto;" />
```

图片插入建议：

- 必须写 `alt`，用一句话说明图片内容，例如 `alt="进入 Google Play 设置"`。
- 优先使用本地图片，不依赖外部图片链接，避免 GitHub Pages 加载不稳定。
- 图片文件名尽量简短、可识别，后续新增图片推荐使用英文或拼音，例如 `google-play-settings.png`。
- 截图中如有账号、手机号、订单号、银行卡、邮箱、验证码、真实地址等信息，发布前必须打码。
- 一张图片只说明一个关键步骤，避免整页长截图堆叠导致读者难以对照正文。

### 图片尺寸建议

根据当前主题正文宽度和字号，图片尺寸先按以下范围控制：

| 图片类型 | 建议最大宽度 |
| --- | --- |
| 竖屏手机截图 | `280px` 到 `300px` |
| 较窄设置页截图 | `260px` 到 `280px` |
| 表单类竖图 | `300px` 到 `340px` |
| 横向网页截图 | `520px` 到 `560px` |
| 架构图、流程图 | `560px` 到 `680px`，以可读为准 |

如果图片文字较小，可以适当放大；如果图片只是辅助说明，应优先缩小，避免压过正文。

### 图片展示写法

需要精确控制尺寸时，优先使用 HTML `img` 标签，而不是 Markdown 图片语法：

```html
<img src="/technological_blog/images/demo.png" alt="示例图片" style="max-width:300px;width:100%;height:auto;display:block;margin:18px auto;" />
```

参数说明：

- `max-width` 控制桌面端最大展示宽度。
- `width:100%` 保证移动端不会溢出。
- `height:auto` 保持原始比例。
- `display:block;margin:18px auto` 让图片居中，并与正文保持合适间距。

## 文字与段落

- 中文正文尽量使用短段落，每段聚焦一个意思。
- 步骤类内容优先使用有序列表。
- 注意事项、限制条件、风险提示可以使用无序列表。
- 链接前后保留自然语义，不裸贴一长串链接，除非链接本身就是操作入口。

## 代码与命令

- 命令、路径、文件名使用行内代码格式，例如 `npm run build`、`source/_posts/`。
- 多行代码块标注语言类型，例如 `bash`、`yaml`、`json`、`python`。
- 代码块前后说明它的作用，不只贴代码。

## 发布前检查

发布或提交前建议检查：

- 文章标题、分类、标签是否合理。
- 图片路径是否能在构建后正常显示。
- 图片尺寸是否和正文比例协调。
- 是否存在敏感信息。
- 是否能成功构建：

```bash
npm run build
```
